# requirements.lock.txt — 完整锁定的依赖清单（构建可复现，P2-2）
#
# 来源：从经过完整回归验证的开发 venv 直接 `pip freeze` 生成（含传递依赖与
# 开发工具 ruff/pytest）。刻意不用 pip-compile 解析最新版：requirements.txt
# 的 >= 约束会解析到未经验证的新版本（实例：flet 0.85.3 曾导致 GUI 无法启动，
# 本项目适配的是 0.85.2）。锁定文件记录"已知可用"，而非"最新可装"。
#
# 用途：
#   打包 / CI / 新环境搭建： pip install -r requirements.lock.txt
#   日常表达意图仍看 requirements.txt（宽松约束）
#
# 再生成（升级依赖后）：
#   1. 在 venv 中升级目标包并跑完整回归（pytest + 实际转换一次）
#   2. .venv/Scripts/python -m pip freeze > requirements.lock.txt（保留本头部）
#
# 注意：本锁定含 onnxruntime-gpu（NVIDIA/开发/CI 目标）。DirectML 分发目标
# 需要另一份锁定（onnxruntime-directml 替换 onnxruntime-gpu），在准备该
# 分发渠道时按同样流程从对应验证环境生成。
#
# 已剔除交叉分支污染（发现于依赖漏洞扫描审计）：开发 venv 同时装过
# exp/jianpu-vlm-ocr 分支手动安装的 llama-cpp-python（main 分支代码完全不
# import 它），首次 freeze 把它和它的专属依赖一并冻了进来——包括无后缀的
# CUDA 13 运行时包（llama-cpp-python 的 cu132 wheel 专用；main 分支的
# onnxruntime-gpu 用的是 nvidia-*-cu12 这套，与之无关，予以保留）。
# 已删除：llama_cpp_python, diskcache, Jinja2, MarkupSafe,
#         nvidia-cublas（无后缀）, nvidia-cuda-nvrtc（无后缀）,
#         nvidia-cuda-runtime（无后缀）。
#
# 2026-08-14 依赖巡检「清理批」（本文件与 requirements.lock.directml.txt 同步改动）：
#   移除 2 个死依赖——
#     musicxml==1.4    全仓库（含 omr_engine/homr 子模块）零 `import musicxml`，
#                      homr 自己的 pyproject.toml 也不依赖它；且 1.5~1.6.1 全部
#                      声明 requires_python "<3.13"，本项目跑 3.14 根本装不上。
#     pypdfium2==5.11.0 PDF 预览在 0.5.0 已移到前端 pdf.js，Python 侧零调用点。
#   小版本升级 14 个：anyio / certifi / cffi / chardet / charset-normalizer /
#     colorlog / omegaconf / packaging / pillow / protobuf / pypdf / ruff /
#     tqdm / typing_extensions。
#   验证：Input/image_test3.png 走 HOMR 端到端跑通，改动前后 .mid / .jianpu.txt /
#     .source.png 逐字节一致，PDF 字节数一致；归档 MusicXML 只差 music21 每次
